# 蓝牙导航与高德 App Wi-Fi 投屏

## 原项目复核

复核原仓库当前 README、docs/GATEWAY_SETUP.md 和 backend/src/map-tiles.js：作者使用高德 Web 服务进行搜索与路线计算，周边底图来自 OSM/Protomaps；PMTiles 构建清单和缓存决定底图版本。它并非高德 App 投屏，也不能消除 OSM 缺路和更新延迟。缩短本地缓存时间不能补出数据源未收录的支路。

参考：https://github.com/mx3353672833-debug/moto-gps-waveshare/blob/main/docs/GATEWAY_SETUP.md

## A：保留独立蓝牙导航

手机加密保存高德 Web 服务 Key，调用电动车路线接口，发送导航数字、转向、局部几何和周边矢量场景。此模式保留自定义配色、车辆 GPS、锁屏导航会话。当前周边底图仍是 OSM/OpenFreeMap，不能承诺与高德 App 的地图覆盖及更新时效一致。

0.5 的修复已加入：手机导航与屏幕使用相同朝向、缩放和设备确认的裁剪场景；设备预览改为真实场景；附近建筑随同提交。实机已确认 192 段道路、16 栋建筑、±500 米地图提交。六种朝向下 550 条地图绘图线段与生产 TFT 绘制程序对照通过，坐标误差不超过 1 像素，颜色、线宽一致。

## B：高德 App 画面投屏

Android MediaProjection 采集用户明确选择的高德 App 窗口，在手机上等比缩放到 480×320，以 JPEG 经本地 Wi-Fi 发送到 ESP32。画面只在内存中处理，不写入截图文件，不使用高德 Web 服务 Key，也不重新拼接 OSM 路网。显示内容取决于高德 App 当时实际呈现的画面。

手机入口：“我的 → 高德 App · Wi-Fi 投屏（实验）”。每次启动必须按 Android 系统提示授权。Android 14 及以上可选择只共享高德 App。0.7 默认“地图放大投屏”，按 3:2 裁剪中部地图并铺满 480×320，裁剪中心略向上偏以减少底部面板占用。另有“完整画面投屏”，保持整个 App 画面比例，竖屏可能有黑边；横屏通常更易阅读。裁剪模式不会补画被裁掉的转向栏，语音和操作仍在手机。

0.8 默认使用手机个人热点：手机保持原上网 Wi-Fi，屏幕作为 Wi-Fi 客户端加入手机 2.4GHz 热点。热点名称与密码由原生安全弹窗输入，经加密 BLE 特征 a005 发给屏幕；屏幕保存到 NVS，并通过同一特征回报局域网地址。手机不再请求连接 MOTO SCREEN，不绑定／切换上网网络；投屏 TCP 直接访问热点内屏幕地址。旧 MOTO SCREEN AP 保留为固件兼容入口，0.8 手机默认不使用它。

启动投屏并获得授权后，结束助手自己的导航，蓝牙连接保留。停止投屏或数秒无图像后，显示屏退出图像显示，回到原导航／待机渲染。

Android 官方依据：https://developer.android.com/media/grow/media-projection

## 图像协议

ESP32 热点客户端地址由 BLE 自动读取，TCP 端口 `8091`。兼容 AP 地址为 `192.168.4.1`。单连接单帧：`NVJ1` + JPEG 长度（u32 大端）+ 序号（u32 大端）+ CRC32（u32 大端）+ JPEG。接收容量上限 65536 字节，分段接收超时 2500ms；完整接收、CRC 与 JPEG 首尾标识校验通过后回复 `OKAY`，才交给屏幕 JPEG 解码。确认代表帧完整接收，不能代替目视验收。

0.7 手机目标采样间隔 150ms，JPEG 质量 50，使用缓冲整帧写入及 TCP_NODELAY，避免拆分小包的等待；发送忙时丢弃新采样，不排队积压旧画面。实际帧率、延迟和 Wi-Fi／蓝牙共存尚待实机测量，不承诺视频级流畅。

旧蓝牙协议不传整幅画面。目前固件 MTU 185，手机每次写入后延迟 15ms，仅原始 480×320 RGB565 一帧就有 307200 字节；现有实现不适合直接承担连续投屏。

## 验证边界

安卓 0.7 APK 编译和签名通过。新固件已通过 COM7 写入 ESP32-S3 并校验哈希，程序占 46%、静态变量占 15%；开机日志确认 Wi-Fi 图像服务启动。

0.6 初次投屏实测：设备累计确认接收 78 帧，用户确认显示出手机画面，并反馈整幅竖屏过小、更新卡顿。Wi-Fi 与蓝牙同时工作时，日志显示 BLE=1、ENC=1、READY=1，没有协议错误。

据此实现 0.7 的 3:2 地图裁剪、150ms 采样和传输优化；新版已覆盖安装，比例和性能改善的实测结果需新会话授权后补记，不能把目标采样率当作实际显示帧率。

安装包：software/android_nav/output/nav-screen-dual-mode.apk。
固件：output/firmware/dual-mode-20261030/，包含合并镜像和 SHA256.csv。
可重建脚本：software/phone_ble_nav/build_wifi_mirror.ps1；加 -Upload 后上传（默认 COM7）。


## 手机联网约束（实机确认）

系统 Wi-Fi 能力检查：`STA + STA Concurrency Supported: false`，`STA + AP Concurrency Supported: true`。因此当前屏幕 AP 方案会占用手机唯一的 Wi-Fi 客户端连接，不能满足“手机仅靠原 Wi-Fi 上网”的条件。不能要求用户断开唯一的上网连接来完成投屏。

用户已确认：个人热点开启后，原 Wi-Fi 仍连接且能上网。已实现 0.8 手机热点配置、固件 STA 接入、BLE 自动地址发现、直连热点客户端的 TCP 投屏；APK 已覆盖安装，固件经 COM7 写入并通过哈希校验。原有 BLE 会话在新固件上实测 BLE=1、ENC=1、READY=1。Java BLE golden / navigation 124 项通过。热点凭据尚待用户在手机原生弹窗输入，因此热点链路和新参数下的帧率暂未验收。

手机“蓝牙网络共享”不能替代上述局域网：ESP32-S3 官方仅支持 BLE，不支持传统蓝牙，不能直接使用传统 PAN/BNEP 共享通道；现有 GATT BLE 导航与该功能不同。参考：https://docs.espressif.com/projects/esp-idf/en/v5.2/esp32s3/api-guides/bluetooth.html
