# 低预算圆屏高德导航终端：采购与制作方案

> 2026-10-05：本文保留为早期独立 GPS / 热点方案的历史记录。当前采用安卓手机定位与路线规划、BLE 传输、ESP32-S3 大屏显示；手机实机操作请按同目录《手机蓝牙导航使用说明.md》进行，无需外接 GPS 模块。

更新：2026-09-25。面向 Windows 电脑、iPhone 个人热点、大学课程实物作业。目标外观参考用户提供的照片：黑色圆屏、白色路线、醒目的转向箭头和距离。预算为采购预留值，不是商家实时报价。

## 1. 最终交付目标

1. 一台能 USB 供电的圆屏实物，正面看不到杜邦线，能放在桌上演示。
2. GPS 模块在室外取得位置；ESP32-S3 连接 iPhone 热点并调用高德 Web 服务 API。
3. 按键从预设目的地中选择一个，屏幕显示高德规划的道路路线、下一步转向和沿路线剩余距离。
4. 走动或骑行时更新位置；偏离路线明显且持续数秒后重新规划。
5. 室内通过录制的 GPS 数据演示整套流程，演示界面明确标注“模拟”。

这是教学样机。第一版屏幕绘制“已选路线”的真实道路形状，但没有照片中所有灰色周边道路。周边道路属于单独的地图数据层；第 9 节给出扩展方法。高德的驾车路线不保证规避电动车、摩托车禁限行路段。

## 2. 系统结构

```text
GNSS 模块 --UART/NMEA--> ESP32-S3 --SPI--> 1.28 英寸圆形 LCD
                           |
                           +--Wi-Fi--> iPhone 热点 --> 高德 Web 服务
                           |
                           +--按键--> 目的地选择 / 重新规划
USB 充电宝或 5 V USB 电源 --> ESP32-S3 开发板
```

不用开发 iOS App，不用 Mac，不用自建服务器。iPhone 在此只提供热点；目的地先写成两个固定坐标，后续再开发配置页。

### 选型检查

- 圆屏必须是 **GC9A01、SPI、240×240**。同尺寸屏可能使用不同芯片，驱动代码不能直接通用。
- 该尺寸可视直径约 32 mm，明显小于参考照片中的圆屏。希望外观更接近照片，可改买更大的圆屏，但成本、外壳尺寸和驱动适配工作会增加。
- S3 板选带 PSRAM，是为了容纳 HTTPS、JSON 解析与路线点；不建议用最便宜、无 PSRAM 的 C3 板做完整路线图。
- GPS 模块应带天线。购买前向卖家核对供电与串口电平，不能仅凭“GPS 模块”四字接线。

## 4. 接线：先在面包板上验证

以下是针对**引出了相应 GPIO 的通用 ESP32-S3 DevKit N8R8**的建议分配。以到手开发板的丝印和模块说明为准；若引脚未引出，先调整代码与接线表，不要猜测。

| 圆屏模块 | ESP32-S3 | 作用 |
|---|---|---|
| VCC | 3V3 | 仅适用于标称 3.3 V 的模块 |
| GND | GND | 共地 |
| SCL / SCK | GPIO12 | SPI 时钟 |
| SDA / DIN / MOSI | GPIO11 | SPI 数据 |
| CS | GPIO10 | 片选 |
| DC | GPIO9 | 命令/数据 |
| RES / RST | GPIO14 | 复位 |
| BLK / BL | GPIO13 | 背光控制；若模块要求固定高电平，按其说明接 3V3 |

2026-09-29 实物核对：到手圆屏背面排针丝印依次为 `GND、VCC、SCL、SDA、RES、DC、CS、BLK`。这块屏的 `SCL/SDA` 用作 SPI 时钟/数据，按上表接线，不按 I²C 接法。照片中屏幕排针靠近面包板侧边电源轨；电源轨沿长度方向连通，**不能把屏幕 8 个排针插在同一条电源轨**。优先用母对公杜邦线：母头接屏幕排针，公头插到 ESP32 对应引脚所在的普通横排；接线前拔掉 USB，全部接完核对后再上电。屏幕照片未显示供电额定值，首次只从 ESP32 的 `3V3` 供电，不接 `5V/VIN`。

| 其他模块 | ESP32-S3 | 说明 |
|---|---|---|
| GNSS VCC | 3V3 | 仅在模块支持 3.3 V 供电时这样接 |
| GNSS GND | GND | 共地 |
| GNSS TX | GPIO4 | ESP32 串口接收；一般无需接 GNSS RX |
| 按键 A 两脚 | GPIO5、GND | 代码设 `INPUT_PULLUP` |
| 按键 B 两脚 | GPIO6、GND | 代码设 `INPUT_PULLUP` |

先用 USB 给开发板供电，**不要把车载电源或锂电池直接接到 3V3 引脚**。完成接线后用万用表检查 3V3 与 GND 没有短路，再插 USB。

## 5. Windows 软件准备

这台电脑的实际安装、开发板识别和自检结果见 [Windows 软件准备检查单](Windows_软件准备检查.md)。ESP32-S3 N8R8 已在 COM7 完成上传和运行时 8 MB Flash / 8 MB PSRAM 核验。

1. 安装 Arduino IDE 2.x。安装 Espressif 的 `esp32` 开发板包，在板卡列表中选择与购买板型对应的 ESP32-S3 开发板；确认 USB 串口可见。
2. 安装库：`LovyanGFX`（GC9A01 显示）、`TinyGPSPlus`（NMEA 定位数据）、`ArduinoJson`（高德 JSON）。Wi-Fi、HTTPS 和 HTTPClient 使用 ESP32 板包提供的库。
3. 先上传 Blink 或串口输出程序：串口监视器能看到循环计数，证明驱动、端口和烧录成功。
4. 为项目建目录 `round-nav/`。把热点名称、密码、高德 Key 放在本地 `secrets.h`，不要把这个文件上传到公开仓库。

软件入口：[Arduino IDE](https://www.arduino.cc/en/software)、[ESP32 Arduino 文档](https://docs.espressif.com/projects/arduino-esp32/en/latest/)、[LovyanGFX](https://github.com/lovyan03/LovyanGFX)、[TinyGPSPlus](https://github.com/mikalhart/TinyGPSPlus)、[ArduinoJson](https://github.com/bblanchon/ArduinoJson)。

## 6. 按顺序完成各模块

### 第一步：点亮圆屏

在 LovyanGFX 中选 GC9A01，设置 240×240、SPI 引脚与背光脚。先显示黑底、白色十字和 `NAV READY`；再画圆形边框、粗白折线、左转箭头和 `32 m`。这一步完全不用 GPS 和网络。验收：连续显示 10 分钟不花屏、不复位。

### 第二步：读取 GPS

ESP32 的 UART RX 用 GPIO4 接模块 TX，按卖家资料设置波特率，常见默认值是 9600，但以到手模块为准。用 TinyGPSPlus 解析 NMEA，串口打印经度、纬度、卫星数、定位是否有效和数据年龄。到室外无遮挡处等待首次定位；室内无法定位并不表示模块故障。验收：静止时坐标在合理范围，移动时坐标随之变化；无定位时屏幕显示“等待定位”，不得使用 `0,0` 请求路线。

### 第三步：申请并单独测试高德接口

在高德开放平台创建 **Web 服务 API Key**，于 Windows 浏览器先测试路线规划 2.0：

```text
https://restapi.amap.com/v5/direction/driving?origin=经度,纬度&destination=经度,纬度&strategy=32&show_fields=polyline,navi&key=你的KEY
```

坐标顺序必须是**经度、纬度**。检查 `status=1`，并确认 `route.paths[0].steps` 有 `instruction`、`step_distance`；请求 `show_fields=polyline,navi` 后检查各 step 的 `polyline`、`navi.action`。先在浏览器获得有效响应，再开始写 ESP32 网络代码。Key 的实际配额和资格在自己的高德控制台核对。

### 第四步：解决坐标系差异

普通 GNSS 输出 GPS/WGS84 坐标；高德路线使用高德坐标。调用高德[坐标转换接口](https://lbs.amap.com/api/webservice/guide/api/convert)，把 GPS 坐标转换后再作为起点，并把后续定位转换到同一坐标系再与路线比较。若跳过这一步，屏幕上的当前位置和道路可能相差数百米。联调阶段可每隔几秒转换一次；响应失败时保留上次有效位置并显示网络状态，不要反复快速重试。

### 第五步：ESP32 联网并取得路线

打开 iPhone 个人热点，让 ESP32 连上；先请求一个小型 HTTPS 测试地址确认网络，再请求高德。检查 HTTP 状态和 JSON 的 `status/info/infocode`，设置超时、失败提示和重试间隔。只保留所需字段与一条路线；解析返回的 step 折线与动作，限制最大点数，超出时抽稀显示。不要在每次屏幕刷新时调用 API：选择目的地、首次定位、偏航确认后才请求路线。

### 第六步：把路线画到圆屏上

将各 step 的经纬度点转换成屏幕局部坐标：当前位置固定在圆屏中心偏下，路线画成白色粗线，当前位置用白色三角形；下一动作箭头放左下，距离用大数字。黑色背景只重绘变化区域或使用显存缓冲，避免闪烁。显示模块首先不画高德地图底图；路线本身仍来自高德的真实道路坐标。

### 第七步：实现“下一步提示”

沿路线预先累计各线段长度。每次得到有效定位后，找到靠近当前位置的路线线段，估算路线进度；下一 step 终点与当前进度的**沿路线距离**就是要显示的“还有多少米转弯”。加时间和距离迟滞，避免 GPS 漂移使提示在相邻步骤间跳动。仅当连续多次偏离路线且距离明显超阈值时重新规划，并设置最短重算间隔，避免耗尽配额。

### 第八步：目的地交互与室内演示

先在代码里写两个学校附近的公开地点坐标。按键 A 切换目的地，按键 B 开始/停止导航；屏幕显示目的地名称。另建“模拟”模式，按录制好的路线坐标逐点播放，屏幕角落显示 `DEMO`。课堂室内演示使用这个模式，室外演示再切换真实 GPS。不要把模拟位置显示成真实定位。

## 7. 外壳与成品组装

1. **联调成功后**测量屏幕 PCB、开发板、GPS 模块、天线和 USB 插头的实际尺寸。
2. 画圆形前框与加厚后壳，前框只露出圆形玻璃，方形屏幕 PCB 藏在壳内。圆屏周围留装配余量；USB 口和两枚按钮留开孔。
3. GPS 陶瓷天线应朝向天空，避免被金属壳遮住。优先用塑料外壳、尼龙柱和螺丝；无打印机可使用通用塑料项目盒加圆形面板。
4. 面包板跳线仅用于调试。提交实物前改成焊接或可靠接插件，固定导线并做好绝缘；轻晃外壳时不得重启。
5. 先做桌面支架。照片里的车把安装件可以作为外观扩展；开发板样机未做防水、抗振和骑行安全验证，展示时不依赖上路测试。

## 8. 验收与课程展示

| 检查 | 通过标准 |
|---|---|
| 屏幕 | 黑底路线、箭头与距离清晰；运行 10 分钟无花屏 |
| GPS | 室外有有效定位；无定位时状态明确 |
| API | 浏览器与设备均能取到同一组起终点的道路路线 |
| 路线提示 | 模拟经过路口后切换到下一动作，距离基本单调减少 |
| 断网 | 显示网络丢失与上次路线，不错误声称“实时” |
| 偏航 | 连续偏离后才重算，短暂漂移不重复请求 |
| 实物 | 外壳固定，USB 供电稳定，按键可用 |

展示顺序：先展示采购与接线照片 → 实物上电 → 按键选择目的地 → 现场连接热点并取得高德路线 → 室内 DEMO 播放转弯提示 → 说明室外 GPS 测试记录。保留串口日志和 API 响应的脱敏截图，不公开 Key 或个人轨迹。

## 9. 可选：更接近参考照片的灰色周边道路

驾车路线 API 返回的是规划路线，不返回屏幕附近所有道路。要画照片中的灰色路网，需要再获取地图数据。课程时间有限时，建议先选校园周边一个小区域，从 OpenStreetMap 获取该区域道路数据，转换成简化折线存到板上，灰色绘制并保留 `© OpenStreetMap contributors` 署名；该扩展仅覆盖预存区域。全国范围的实时底图还需要瓦片请求、缓存、图片解码、坐标投影和数据授权审查，工作量明显上升，不宜列为第一版交付门槛。

## 10. 时间安排与停损点

| 阶段 | 建议时间 | 完成标志 |
|---|---:|---|
| 采购与板卡点亮 | 2–4 天 | 串口、圆屏单独工作 |
| GPS 与高德接口 | 3–5 天 | 室外坐标、浏览器和板端路线请求通过 |
| 路线绘制与转向判断 | 5–8 天 | DEMO 模式整段路线可播放 |
| 外壳与演示材料 | 2–4 天 | 可靠实物、照片和简短说明 |

如果高德接入或 GPS 定位超过预期，仍应保留“路线 JSON 文件离线播放”的课程演示模式，保证作业有真实开发板、真实屏幕和可重复的功能展示；现场网络成功后再展示在线规划。
