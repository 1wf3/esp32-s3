# 电脑 HTML 与导航屏同步调试

在项目根目录运行 `启动电脑同步调试.ps1`，保持启动窗口运行，再访问 http://127.0.0.1:8790/ 。当前服务只监听本机，不向局域网开放。

1. 开发板保持 USB 连接，手机应用在“我的”页关闭会话。
2. 页面点击“连接导航屏”，等待“加密 BLE · Ready”。
3. 点击“开始同步导航”，首次路网加载需要等待。之后可以暂停、前进 100 米、改变速度、模拟定位失效、恢复定位或结束导航。
4. 手机界面的“设备 → 导航显示”可修改配色和车辆图标，再点击“同步到设备”。以“设备回读一致”为确认。
5. 调试结束先点击“结束导航”和“断开电脑连接”，再关闭启动窗口。重新启动服务后刷新 HTML；旧页面中的会话令牌会失效。

`output/previews/手机应用新版界面预览.html` 已接入本地调试服务。也可在外部浏览器直接打开此文件，但必须先启动服务。内置浏览器使用上面的本机 HTTP 地址，因为它不允许自动操作 file:// 页面。

左侧是手机界面，右侧是导航屏的同源渲染预览。480×320 预览使用生产固件同一份 PhoneRenderer，导航速度、距离、路线、路网和配色来自本次发送数据。它不是开发板的屏幕截图；是否实际接收，以提交确认、配色回读和串口 Ready/速度/路线/路网共同核对。

演示使用仓库内公开济南路线和真实 OpenStreetMap / Protomaps 道路数据。屏幕端按当前位置裁剪附近道路，不只显示主路线。位置和速度是明确标记 DEMO 的电脑模拟值，不用于实地导航。真实目的地搜索及播报继续在安卓应用中测试。

车辆位置独立读取开发板 ATGM336H 的加密蓝牙通道。未有效定位时显示等待搜星，不显示模拟车辆位置；定位只在蓝牙范围内读取。目前室内尚未验证有效车辆定位。电量、鸣笛、亮度控件保持删除。

已经发现并处理：Python 3.13 与已有 WinRT 3.12 扩展不匹配（启动器选择已有 3.12）；Windows 协商到 20 字节帧时握手兼容；HTML 脚本换行语法；GPS 失效后箭头显示；蓝牙读写超时和失败清理。串口和蓝牙同时无响应时可能需要重新插入开发板 USB。不要在串口监视占用 COM7 时使用其他烧录工具。

复测命令（已连接开发板后执行）：`python software/pc_debug/test_integration.py`。全部通过后会生成 `build/pc_debug/test-results.json`，包含实际串口数值和提交确认数量，不记录车辆坐标或会话令牌。固件渲染器如有修改，可用 `software/pc_debug/build_renderer.cmd` 重新编译电脑预览。

本次实机复测：11 项集成检查全部通过，包括定位失效与恢复、前进 100 米、结束导航，以及配色/图标/四项颜色回读。最终屏幕接收 131 段真实道路，20 字节分包模式通过，Ready=1，速度=24 km/h，未发现协议错误。结果见 build/pc_debug/test-results.json。

连接顺序修正：Windows 打开串口可能导致开发板重启，因此先启动串口并等待开发板状态，再扫描和连接蓝牙。路网中间分包使用设备支持的无响应写入并限速，最后一包等待 GATT 响应；整条路网及路线仍需应用层提交确认。

2026-10-11 持续同步验证：60 秒内新增 27 份导航快照，串口 Ready 与路线持续有效，无协议错误。记录见 build/pc_debug/soak-results.json。自动检查结束后保持蓝牙连接，页面可继续手工调整演示进度、速度和配色。车辆 GPS 尚无有效卫星定位，未完成室外定位验证。

显示流畅度优化已更新：当前协商 182 字节帧，SPI 40 MHz，真实路网移动实测 5.4～6.1 FPS，45 秒无协议错误。详见 显示流畅度优化记录.md。
