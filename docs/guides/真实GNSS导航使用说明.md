# 真实 GNSS 导航：洛阳应天门

## 硬件及程序
- 本次仍使用已经点亮的 GC9A01 240×240 圆屏；ST7796S 到货后另做驱动及布局适配。
- GNSS：VCC → ESP32 的 3V3，GND → GND，TX → GPIO17。RX、PPS 不接。不要改成 5V。
- 圆屏：SCL12、SDA11、DC9、CS10、RES14、BLK13，VCC3V3，共地。
- 草图：`software/round_screen_test/round_screen_test.ino`。
- Arduino IDE：ESP32S3 Dev Module，Flash8MB，PSRAM OPI，串口 COM7（插拔后可能改变），监视器115200。

## 上电顺序
1. 天线插头扣在模块 IPEX 底座上，陶瓷面向上，放在室外开阔位置。
2. iPhone 开启个人热点，名字 iPhone，开启最大兼容性。密码沿用本地文件。
3. 上电后等待 GNSS 定位与 Wi-Fi 连接。初次获取路线还需要网络校时。
4. 程序用真实 GNSS 起点请求高德路线，目的地为洛阳应天门 POI（112.460886,34.676011，高德坐标）。
5. 黑底透视路线界面中，浅色为未驶过路线，灰色为已经经过部分；顶部弧显示当前路线完成比例；右侧显示 GNSS 速度；下方为下一步骤的距离；LEFT 为剩余几何路线长度。

## 状态和操作
- WAIT GNSS FIX：等待有效定位，要求位置/HDOP不超过3秒，HDOP≤5。
- LIVE GNSS：真实定位驱动显示。静止时低于1.5km/h的速度显示0，抑制漂移。
- GNSS LOST：定位过期，速度显示--，进度冻结，转向距离显示--m。
- OFF ROUTE：距受连续性约束的路线匹配点超过45米，暂停更新进度。持续15秒后尝试重规划，自动请求之间至少60秒。
- DONE：剩余几何路线少于40米且距离规划终点少于25米，连续3个定位样本满足后显示。
- 热点断开：已有路线继续使用真实GNSS；重新规划要联网。
- 串口监视器输入 `r` 后回车：从最新定位重新规划，手动请求至少间隔10秒。
- 串口摘要的 OFFSET 为路线匹配偏离距离，单位米；ROUTE 中前一个数为已走路线长度，后一个数为剩余长度。
- 输入 `p` 后回车：只在本地串口显示一次 WGS84 经度、纬度。默认摘要不打印坐标或密钥。

## 坐标及数据边界
GNSS GPS坐标不能直接与高德路线叠加。每次规划先调用高德坐标转换接口，使用官方转换结果作为起点，并校准本地 WGS84→GCJ02 近似计算。行进时在本地转换，避免每个定位样本都请求网络；这是教学样机的近似转换，不能保证官方接口逐点精度。

当前接口仍沿用驾车规划，不等同于电动车专用路线。匹配采用局部平面投影、线段最近点及连续性限制；复杂交叉、平行道路、隧道等环境需要进一步实测。进度允许随位置回退，不是累计里程表。重规划后弧形进度从新路线重新计算。剩余距离是polyline几何长度，可能与高德道路距离略有差异。

高德本次返回所选路线及转向步骤，没有返回周围完整道路网；程序已去掉原先虚构的路网。当前绘制真实选定路线的透视效果，完整地图平移、缩放及真实周边路网尚未实现。

## 验证
程序启动包含路线投影、偏离距离、连续性限制和双精度坐标的基本自检，串口应显示 NAV math self-test PASS。

实地验证建议：携带样机在开阔处步行一小段，确认定位变化后进度、剩余距离及已驶过颜色变化；短暂遮挡/断开GNSS数据时应出现GNSS LOST且进度冻结。实际行进、偏航重规划和终点到达需要现场确认，不能仅由静止桌面测试认定成功。
