# ATGM336H-5N-31 首次测试

## 断电后接线

按模块和开发板丝印辨认，不能按排针位置猜测。

| GNSS模块 | ESP32-S3 |
| --- | --- |
| VCC | 3V3（首次测试先用3.3V） |
| GND | GND |
| TX | GPIO17（板上标17） |
| RX | 不接 |
| PPS | 不接 |

GPIO17与当前圆屏的GPIO9～14不冲突。不要把模块TX接到开发板用于USB串口的TX/RX引脚。
芯片本身供电为2.7～3.6V；这个转接板是否支持5V需要卖家资料确认，不能凭裸模块参数判断整板支持5V。

天线的陶瓷面朝天，照片中的金属底板面朝下。保留已接好的天线线缆。

## 在Arduino IDE中上传

1. 打开 E:\电动车导航9.25\software\gnss_test\gnss_test.ino。
2. 保持此前已验证的 ESP32S3 Dev Module 开发板配置，选择实际连接的COM端口（此前是COM7）。
3. 点击左上角验证，然后点击上传箭头。本测试会暂时替换板上的导航程序，原文件仍保存在项目里。
4. 打开串口监视器，波特率设为115200。模块串口为9600，两个串口的速率不同是正常的。
5. 按一次开发板RST。前15秒显示原始NMEA，随后每秒报告一次解析结果；发送r可切换原始输出。
6. 到室外无遮挡处保持静止，首次测试可留出3～10分钟；不承诺在室内或固定时间内定位。

## 判断结果

- `bytes=0` / `NO UART DATA`：未收到数据，先检查供电、共地、TX到GPIO17和接触情况。
- 有`$GNGGA`、`$GNRMC`或其他`$GP...`/`$GN...`行：串口已通，但不代表已经定位。
- `WAIT FIX / STALE FIX`：暂时没有新鲜有效的位置；检查天线朝向和天空遮挡。
- `FIX lat=... lon=...`且持续更新：已经得到有效定位，可以进入导航集成。
- 字节增长但`valid_sentences=0`：检查波特率、是否乱码、接线是否可靠；默认从9600开始，不先修改模块设置。

程序依赖已安装的TinyGPSPlus。当前测试不访问网络、不读取热点密码或高德Key，也不驱动屏幕；圆屏画面不作为成功标准。

下一阶段需要确认GNSS输出坐标基准与高德GCJ-02的转换，然后加入真实位置、速度、路线进度和偏航判断。静止时航向及低速速度可能抖动，应在集成时处理。
